## Kimi Code CLI 1.9.0

After the adapters were split by host syntax, this isolated public-repository command

```bash
npx plugins@1.3.4 add veriglow/citeanything-plugin --target kimi --scope user --yes
```

registered and enabled the package in Kimi's managed plugin store with one Skill and an inline
`type: "http"` MCP server. This passes package registration. Standalone `kimi mcp` commands use the
separate `~/.kimi/mcp.json` configuration path and do not, by themselves, prove that the managed
plugin's MCP is active inside an agent session.

The native fallback passed DCR, browser OAuth, and exact nine-tool discovery:

```bash
kimi mcp add --transport http --auth oauth citeanything https://citeanything.app/mcp
kimi mcp auth citeanything
kimi mcp test citeanything
```

The current Python MCP/FastMCP client required two safe interoperability normalizations on the
server: its default DCR auth method is normalized to the public `none` method, and its issuer-root
resource alias is canonicalized to `https://citeanything.app/mcp`. PKCE remains mandatory and token
audience remains the exact MCP URL.

An agent-driven read call was not evaluated because the local Kimi account's configured model was
unavailable. MCP authorization and `tools/list` were successful independently, so the native MCP
fallback remains documented until the combined plugin-store, agent-session, OAuth, and tool-call
path is verified.

  reliable.
- `--scope project` may still write host-level plugin caches or configuration.

  not sufficient evidence that tools are available.

  installation registration rather than only writing cache and config entries.

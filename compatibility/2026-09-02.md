# Host interoperability — 2026-09-02

This report records non-secret release-candidate checks against the public
`veriglow/citeanything-plugin` repository and `https://citeanything.app/mcp`. Account identifiers,
OAuth codes, access tokens, refresh tokens, document names, and document contents are omitted.

## Kimi Code CLI 1.9.0

The generic installer copied the package to `~/.kimi-code/plugins`, while this Kimi version reads
MCP configuration from `~/.kimi/mcp.json`; the plugin-provided MCP was therefore not activated by
`npx` alone.

The native fallback passed DCR, browser OAuth, and exact nine-tool discovery:

```bash
kimi mcp add --transport http --auth oauth citeanything https://citeanything.app/mcp
kimi mcp auth citeanything
kimi mcp test citeanything
```

The current Python MCP/FastMCP client required two safe interoperability normalizations on the
server: its default DCR auth method is normalized to the public `none` method, and its issuer-root
resource alias is canonicalized to `https://citeanything.app/mcp`. PKCE remains mandatory and token
audience remains the exact MCP URL.

An agent-driven read call was not evaluated because the local Kimi account's configured model was
unavailable; MCP authorization and `tools/list` were successful independently.

## Cursor Agent 2026.08.31-4057e58

native plugin system. Cursor's own marketplace command indexed the repository as one Skill plus one
MCP server, and the interactive `/plugin` flow installed it for the user. A runtime probe detected

The test machine did not have the Cursor desktop IDE installed, and this Cursor Agent version
directed plugin-provided MCP authentication to the IDE. Browser OAuth and tool execution therefore
remain pending.

## Claude Code 2.1.229

```bash
claude mcp add --scope user --transport http citeanything https://citeanything.app/mcp
```

The installed CLI's authentication/account probe repeatedly failed to complete within the bounded

## Installer findings

- Concurrent installs should not share the same `plugins` clone cache; sequential installation was
  reliable.
- `--scope project` may still write host-level plugin caches or configuration.
- Target-specific activation must be verified with each host's native MCP view; a successful copy is
  not sufficient evidence that tools are available.
